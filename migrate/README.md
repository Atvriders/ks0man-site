# ks0man.com → ks0man.org

Everything the old domain has to do when the new site goes live.

## What is here

| File | What it is |
|---|---|
| `url_map.csv` | Every old address and where it goes now: 479 rows — every file in the mirror, and the files the old pages linked to that the mirror does not hold. |
| `ks0man_com.htaccess` | The same map as Apache rewrite rules, ready to drop in the document root of ks0man.com. |

Both are generated by `tools/build_redirects.py`, which decides from the
repository what each old address is, then asks the **live** site where that thing
lives rather than assuming an information architecture:

```
WP_USER=… WP_APP_PASSWORD='xxxx xxxx …' \
python3 tools/build_redirects.py --site https://ks0man.org --verify
```

`--verify` sends a request for every target before the files are written. The
map that came out of the original study was never checked that way, and it sent
`/newsletter_03-22.pdf` to `/archive/minutes-2022-03-11/` — a URL that has never
existed, because a publication permalink carries its year. Roughly half its rows
were wrong.

## What the map does with each kind of thing

| Rows | Old URL | Goes to |
|---:|---|---|
| 266 | a newsletter, minutes, treasurer's or year-end report | the archive record made from that file — including `/newsletter_04-10.pdf` and `/treasurer_03-21.pdf`, which the old newsletters index linked and ks0man.com answered with 404, and `/newsletter_01-17.pdf`, a copy of the February 2017 minutes, which opens that record |
| 168 | a photograph, document, video or graphic | the file in the media library at the size ks0man.com served it: for nine photographs the migration shipped a smaller copy under the plain name, and the old address goes to the original that shipped beside it, never to WordPress's `-scaled` derivative |
| 26 | a page | the page that replaced it |
| 2 | `index.htm`, `index.html` | the front page |
| 9 | a file the old pages linked to that was never on the site | `/archive/gaps/`, which names it — and the Salina hamfest mailer, which the folder kept under another name, goes to that file |
| 5 | a link on the old links page or home page that lost its site's name (`files/file/Clubs/Tips and Tonics …`) | the document on the other site, at the address the webmaster's own copy of the page gives |
| 3 | two stylesheets, and a link to Facebook on the old home page that lost its site's name | `410 Gone` |

All 471 targets on the site were requested and answered 200 when the files were
written. Anything not named falls through to the front page rather than a 404.

The same decisions are in `wp/plugins/maars-core/inc/legacy-map.php`, which the
site itself uses to answer an old address that reaches **ks0man.org** — the old
site's other name, which the webmaster's pages linked. Pointing ks0man.com at
the new site would make every row here work with no rules on the old host.

## Before you deploy it

1. The rules are relative to the document root; if ks0man.com serves out of a
   subdirectory, add `RewriteBase`.
2. `mod_rewrite` must be enabled and `AllowOverride` must permit `.htaccess`.
3. Re-run the generator after any change to the archive: a record that gains a
   permalink, or a file that is uploaded later, moves a row.
4. Keep the old domain alive. A 301 that nobody serves is a link that rots.
